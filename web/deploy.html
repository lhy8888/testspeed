部署教程 · v0.1.1

把测速部署到你的服务器

一条命令安装，后续更新和维护也使用同一个管理工具。适用于公网和企业内网。

单端口 8080默认 8 路并发最多 30 路

安装到服务器

推荐 · Linux / systemd

在目标服务器的终端执行。需要 Linux、systemd、sudo 权限，以及访问 GitHub 的网络；无需安装 Go、Node.js 或 Docker。

首次安装
curl -fsSL https://raw.githubusercontent.com/lhy8888/testspeed/v0.1.1/deploy/manage.sh | sudo bash -s -- install

脚本下载并校验安装包，安装网页和服务，创建 systemd 服务并启动。安装后，在浏览器打开：

http://服务器IP:8080替换为客户端可访问的 IP 或域名

防火墙或安全组允许 TCP 8080 即可。网页、下载和上传都使用同一端口。

更新与日常维护

安装后的管理工具位于 /opt/testspeed/manage.sh。下面的命令都在这台服务器的终端执行。

更新到最新正式版
sudo /opt/testspeed/manage.sh update

更新会重启服务，保留现有配置文件。

查看状态
sudo /opt/testspeed/manage.sh status

查看已安装版本
sudo /opt/testspeed/manage.sh version

实时日志
sudo /opt/testspeed/manage.sh logs

按 Ctrl+C 退出日志查看。

重启服务
sudo /opt/testspeed/manage.sh restart

停止服务
sudo /opt/testspeed/manage.sh stop

启用单端口模式
sudo /opt/testspeed/manage.sh mode websocket

升级旧版后使用；保留监听地址和 TLS 配置。

安装指定版本或回退

update 后可指定版本标签。例如回退到 v0.1.0：

指定版本
sudo /opt/testspeed/manage.sh update v0.1.0

v0.1.0 使用旧的 HTTP 测速。回退时会保留当前管理脚本，之后仍可用 update 更新。版本标签见 GitHub Releases。

卸载与配置清理

下面两种卸载方式按需选择一种。卸载会停止服务并移除已安装程序；默认保留配置文件，便于重新安装。

卸载，保留配置
sudo /opt/testspeed/manage.sh uninstall

如果同时需要删除测速配置，使用：

卸载并删除配置
sudo /opt/testspeed/manage.sh purge

清理范围包含 /etc/testspeed/testspeed.env，同目录的证书及其他文件会保留。卸载后本机管理脚本也会被移除。

文件在哪里

程序与网页
/opt/testspeed/testspeed
管理工具
/opt/testspeed/manage.sh
服务配置
/etc/testspeed/testspeed.env
systemd 服务
/etc/systemd/system/testspeed.service

修改配置后重启服务。使用 HTTPS、自定义地址或离线安装时，参照完整部署文档。

已经使用 Docker？

也可使用 Docker Compose 部署。选择一种部署方式，让网页端口供对应服务使用。

官方 Docker Engine + Compose

需要 Git、Docker Engine 和 Compose 插件。在服务器上执行：

安装并启动
sudo git clone --depth 1 --branch v0.1.1 https://github.com/lhy8888/testspeed.git /opt/testspeed-src
sudo docker compose --project-directory /opt/testspeed-src --file /opt/testspeed-src/compose.yaml up --build --detach
sudo docker compose --project-directory /opt/testspeed-src --file /opt/testspeed-src/compose.yaml logs --follow

源码目录为 /opt/testspeed-src；已存在该目录时参照完整文档处理。默认网页端口为 8080。

Docker 通过 Snap 安装

如果 sudo sh -c 'command -v docker' 输出 /snap/bin/docker，源码应放在 Snap 可读取的目录，并同时指定 Snap 配置。

全新 Snap 部署
sudo git clone --depth 1 --branch v0.1.1 https://github.com/lhy8888/testspeed.git /var/snap/docker/common/testspeed-src
sudo docker compose --project-directory /var/snap/docker/common/testspeed-src --file /var/snap/docker/common/testspeed-src/compose.yaml --file /var/snap/docker/common/testspeed-src/compose.snap.yaml config --quiet
sudo docker compose --project-directory /var/snap/docker/common/testspeed-src --file /var/snap/docker/common/testspeed-src/compose.yaml --file /var/snap/docker/common/testspeed-src/compose.snap.yaml up --build --detach

已经克隆到 /opt 的用户可保留原目录，按完整部署文档创建副本。使用 Snap 配置无需重装 Docker。
