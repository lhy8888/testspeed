部署教程 · v0.1.4

把测速部署到你的服务器

一条命令安装，后续更新和维护也使用同一个管理工具。适用于公网和企业内网。

单端口 8080默认 8 路并发最多 30 路

安装到服务器

推荐 · Linux / systemd

在目标服务器的终端执行。需要 Linux、systemd、sudo 权限，以及访问 GitHub 的网络；无需安装 Go、Node.js 或 Docker。

首次安装
curl -fsSL https://raw.githubusercontent.com/lhy8888/testspeed/v0.1.4/deploy/manage.sh | sudo bash -s -- install

脚本下载并校验安装包，安装网页和服务，创建 systemd 服务并启动。安装后，在浏览器打开：

http://服务器IP:8080替换为客户端可访问的 IP 或域名

防火墙或安全组允许 TCP 8080 即可。网页、下载和上传都使用同一端口。

更新与日常维护

安装后的管理工具位于 /opt/testspeed/manage.sh。下面的命令都在这台服务器的终端执行。

更新到最新正式版
sudo /opt/testspeed/manage.sh update

更新会重启服务，保留现有配置文件。

查看状态
sudo /opt/testspeed/manage.sh status

查看已安装版本
sudo /opt/testspeed/manage.sh version

实时日志
sudo /opt/testspeed/manage.sh logs

按 Ctrl+C 退出日志查看。

重启服务
sudo /opt/testspeed/manage.sh restart

停止服务
sudo /opt/testspeed/manage.sh stop

启用单端口模式
sudo /opt/testspeed/manage.sh mode websocket

升级旧版后使用；保留监听地址和 TLS 配置。

安装指定版本或回退

update 后可指定版本标签。例如回退到 v0.1.0：

指定版本
sudo /opt/testspeed/manage.sh update v0.1.0

v0.1.0 使用旧的 HTTP 测速。回退时会保留当前管理脚本，之后仍可用 update 更新。版本标签见 GitHub Releases。

卸载与配置清理

下面两种卸载方式按需选择一种。卸载会停止服务并移除已安装程序；默认保留配置文件，便于重新安装。

卸载，保留配置
sudo /opt/testspeed/manage.sh uninstall

如果同时需要删除测速配置，使用：

卸载并删除配置
sudo /opt/testspeed/manage.sh purge

清理范围包含 /etc/testspeed/testspeed.env，同目录的证书及其他文件会保留。卸载后本机管理脚本也会被移除。

修改配置后重启服务。使用 HTTPS、自定义地址或离线安装时，参照完整部署文档。

IP、所在地与 ISP/ASN

GeoIP 默认使用 FreeIPAPI 的固定 HTTPS 服务，将公开客户端 IP 发给第三方查询近似网络所在地；私网地址不查询。ISP/ASN 仅显示查询或授权数据库实际提供的信息，缺失时留空。查询失败不影响测速，结果不代表 GPS 位置。

服务器位置可设置 SERVER_LOCATION=中国·上海，内网客户端标签使用 CLIENT_NETWORK_LABEL=上海园区。设置 GEOIP_ENABLED=false 关闭在线和离线查询，保留手填标签。未手动配置时，在线服务器位置只近似反映公网出口。

GEOIP_PROVIDER=auto 默认在线优先，配置 GEOIP_DB_PATH 后用本地 MMDB 补缺或降级；online 仅在线；offline 仅查询已配置的本地库，不调用第三方。数据库须自行获取正确授权，程序不会下载；离线无法探测服务器公网出口，应手填机房位置。

反向代理需显式配置 TRUSTED_PROXIES，默认忽略转发头；库路径、支持的 schema、来源校验与额度说明见部署文档。

可选分享：启用、关闭与数据维护

默认不启用服务器数据库。本地历史和导出直接可用；分享需要用户点击提交，是客户端报告，不是服务器认证的速度证明。

启用 SQLite 分享
sudo /opt/testspeed/manage.sh share on

数据库位于 /var/lib/testspeed/results.sqlite。命令兼容新旧 systemd 安装，设置所需的可写状态目录并重启；默认最多 10000 条、保留 168 小时。

关闭分享并保留数据
sudo /opt/testspeed/manage.sh share off

可配置 SHARE_WRITE_TOKEN 保护新建报告，读取使用分享链接；令牌不用于测速，不出现在共享链接或本地历史。用户可撤销当前页面刚创建的分享。分享报告不包含客户端 IP、所在地或令牌。

关闭、更新、卸载和清理配置都保留分享数据库。备份、恢复、显式删除和 Docker 数据卷说明见完整部署文档。

测试项目与记录

打开测速页的“更多信息 / Show more info”，可以选择完整测速、仅下载或仅延迟。只运行选择的项目；仅下载会跳过上传流量，仅延迟使用小型 HTTP 往返请求。

固定时长、自适应与流量预算

默认固定完整时长：每方向正式计量 10 秒，预热下限 1.5 秒并按 RTT 延长。灰色下载数字来自真实预热数据，最终结果排除预热。

自适应为可选项，正式计量至少 5 秒和 8 个 RTT，连续真实窗口稳定且没有失败或测量调度异常时才提前结束；未稳定则继续到所选最长时长。上传结果由服务器冻结实际收到的字节和实际计量时长。

流量预算按每方向独立计算，包含预热，0 表示不限。已在途数据和有界关闭排空会产生余量，不能当作严格网卡流量封顶。预算在正式计量开始前耗尽时显示“未测”；已有短窗口会标明预算结束，不保证已经充分收敛。

连接稳定性、最近 50 条历史与导出

连接稳定性页面可持续采样 1、2、5 分钟，显示延迟分布 P50/P95/P99、抖动、请求失败率和 CSV。只请求当前节点的小型响应，不开展下载或上传测速。HTTP 请求失败率不是网络丢包率。

网页保留最近 50 条本地历史，可导出单条 JSON、CSV、PNG 或全部历史 CSV，也可清理历史。数据仅留在当前浏览器，不自动上传，导出排除 IP、所在地及令牌。

已经使用 Docker？

也可使用 Docker Compose 部署。选择一种部署方式，让网页端口供对应服务使用。

官方 Docker Engine + Compose

需要 Git、Docker Engine 和 Compose 插件。在服务器上执行：

安装并启动
sudo git clone --depth 1 --branch v0.1.4 https://github.com/lhy8888/testspeed.git /opt/testspeed-src
sudo docker compose --project-directory /opt/testspeed-src --file /opt/testspeed-src/compose.yaml up --build --detach
sudo docker compose --project-directory /opt/testspeed-src --file /opt/testspeed-src/compose.yaml logs --follow

源码目录为 /opt/testspeed-src；已存在该目录时参照完整文档处理。默认网页端口为 8080。

Docker 通过 Snap 安装

如果 sudo sh -c 'command -v docker' 输出 /snap/bin/docker，源码应放在 Snap 可读取的目录，并同时指定 Snap 配置。

全新 Snap 部署
sudo git clone --depth 1 --branch v0.1.4 https://github.com/lhy8888/testspeed.git /var/snap/docker/common/testspeed-src
sudo docker compose --project-directory /var/snap/docker/common/testspeed-src --file /var/snap/docker/common/testspeed-src/compose.yaml --file /var/snap/docker/common/testspeed-src/compose.snap.yaml config --quiet
sudo docker compose --project-directory /var/snap/docker/common/testspeed-src --file /var/snap/docker/common/testspeed-src/compose.yaml --file /var/snap/docker/common/testspeed-src/compose.snap.yaml up --build --detach

已经克隆到 /opt 的用户可保留原目录，按完整部署文档创建副本。使用 Snap 配置无需重装 Docker。

Docker 可选持久分享

需要服务器分享时，在基础配置后增加 compose.share.yaml。它使用持久数据卷，数据库位于 /var/lib/testspeed/results.sqlite：

sudo docker compose --project-directory /opt/testspeed-src --file /opt/testspeed-src/compose.yaml --file /opt/testspeed-src/compose.share.yaml up --build --detach

Snap 换成公共源码目录并同时加 Snap override。后续维护沿用选定的 override；down 保留分享数据卷，down --volumes 会删除数据，仅在确认清除全部分享时使用。Docker 离线 MMDB 需自行提供只读挂载，详见完整部署文档。
